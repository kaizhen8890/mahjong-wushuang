# 表情维护：给执行维护的 AI

这是随包表情维护的唯一操作说明。固定工作区为 `C:/Users/kaizhen8890/Documents/Codex/mahjong-wushuang`。命令从该目录运行，不需要阅读源码或手改 JSON。工具只修改私人表情，公开库保持为空。

## 日常操作：放图，然后运行

1. 把静态 PNG/JPEG/WebP 放入 `private-content/emotes-inbox/`，文件名作为标签（1–40 个字符）。不放子文件夹、说明文档或动画。
2. 运行 `./Manage-Emotes.ps1 --build`。

工具自动检查整批图片、缩小到长边不超过324（不放大）、转换WebP、去重、分配数字编号、登记文件大小和哈希、备份及写入，然后进行完整私人验证构建。原图不删除；同批重复运行不会重复添加。原有101张图的编号、路径和标签不会被重写。

不需要APK时运行 `./Manage-Emotes.ps1`。只看预计结果运行 `./Manage-Emotes.ps1 --preview`；它不写素材或清单。

## 命令

| 目的 | 命令 |
|---|---|
| 检查现有内容，不构建、不推进版本 | `./Manage-Emotes.ps1 --check` |
| 查看编号、标签、退役记录、下一个编号 | `./Manage-Emotes.ps1 --list` |
| 换图，保留编号 | `./Manage-Emotes.ps1 --replace 4000 "C:/图片/新图.png"` |
| 换图并改标签 | 在换图命令后加 `--label "新标签"` |
| 仅改标签 | `./Manage-Emotes.ps1 --rename 4000 --label "新标签"` |
| 退役 | `./Manage-Emotes.ps1 --retire 4000` |
| 撤回一次维护 | `./Manage-Emotes.ps1 --undo 操作编号` |
| 素材已成功，只重试打包 | `./Build-Android.ps1 -Profile private -Validation` |

4000仅为示例；日常添加不用选编号。退役编号永久跳过，原图留在收件箱也不会复活。换过图后旧原图不会被下一次扫描自动加回；如明确需要作为另一张新表情，交开发者处理这一少见情况，不手删去重记录。

## 如何读结果和处理失败

- `passed: true` 表示本次动作成功；`changed: false` 表示检查或没有新变化。
- `messages` 列出每张图的编号或跳过原因；`operation` 是本次备份/回退编号。
- 图片格式、损坏、像素或大小问题：按报错中的文件名移出或重新导出，再运行原命令。原图超过12MB或4000万像素会拒绝；处理后须不超过256KiB。
- 只要有一张图预检失败，整批素材都不写。写入过程失败会恢复；突然断电/关闭后，下次运行先自动恢复未完成操作。不要自行删除 `.mw-writing`、备份或清单。
- 提示“被其他任务修改”：等待另一任务结束后重试；恢复发生冲突时保留现场交开发者，工具不会覆盖后来的修改。
- 提示账本缺文件/多文件/哈希不一致：不要手算哈希补JSON。核对是否有人手动搬图；多余图移回收件箱，缺失或被替换的图从对应备份恢复；不确定时保留现场交开发者。
- APK构建失败：素材成功与打包失败会分别报告。不要重复加图；按构建提示处理，然后只重试打包。空间不足/旧构建未处理时使用工作区既有空间管理流程，不复制新工程绕过。

## 备份与边界

每次维护备份在 `backups/emote-operations/<operation>/`，含修改前后字节、SHA-256和内容包；回退先检查后续修改，有冲突整批拒绝。工具用构建同一把锁，不能与打包/归档/清理同时修改素材。

`emotes.manifest.json` 是工具维护的稳定编号、退役和去重记录；`bundle.json` 中仅表情条目与表情文件账本由工具更新。其他文件账本、音乐、NFC、卡面及其他字段原样保留。不要把这些JSON作为日常人工入口，不要删清单来“重置”。私人原图和备份不能提交公开Git仓库。

验证包版本名带 `-validation`，复用当前versionCode，完整执行测试、内容契约、网页/Android构建、签名和资源哈希核验。它不能归档成正式交付，不推进CURRENT的交付版本。正式交付仍须推进版本号并使用默认构建流程。

## 应用内导入与联网

不需要随APK分发时，在App表情面板使用管理/导入，详见[表情库说明](../docs/emote-library.md)。本工具不修改运行时传输；不同版本的内置编号尚无图片摘要协商，换图后同房间应使用一致版本。

## 正式交付入口（2026-10-16整改）

用户要求正式私人版时，将原维护命令的 --build 换成 --release。它完成素材写入后直接推进版本并构建正式包；不要先打验证包再打正式包。原 --build 仍仅做同版本验证。

核对输出APK和报告后运行 `./Release-Android.ps1 -Profile private -Finish -Reviewed`，统一归档、更新版本门槛和状态、清理本次stage，不上传GitHub。已归档且哈希一致的旧stage才会自动回收；其他任务和未诊断失败构建保持保护。

素材写入成功但构建失败时不要重复导入或手动升版本。查看日志；`./Release-Android.ps1 -Profile private -Resume -Build`可恢复准备中断或找回成功构建；失败构建保留现场供诊断。独立预览正式版本方案可运行 `./Release-Android.ps1 -Profile private`，加 `-Build`才开始。

## 简短输出与保留测试包（2026-10-17）

--list默认最多10条，仅显示编号与名称；--query 关键词可按名称/编号筛选，--offset 10看下一页，--all才全量输出。重复/退役输入默认只计入skippedCount，不逐条打印；确需诊断时用--verbose。

用户要求保留验证包时，保留要求优先，不应因为默认清理规范把包删掉。先运行 `./Manage-Storage.ps1 keep-validation 构建编号`预览，追加`--apply`核验并独立保存APK和报告到releases/validation/kept-构建编号。它不变成正式版，也不改变CURRENT交付记录；不会自动删除原stage。确认副本后，如不需要临时工程，可另行cleanup该构建 --rehearsal --apply。已保留APK不会被正式版轮换清理删除。
