# beta24：Android 影片压缩与无双歌曲衔接

> 2026-10-10 文档核对：下列版本号和验证描述属于beta24实施记录；当前本地为beta26，压缩与音乐机制继续沿用。现行构建入口见 [包体维护](APK-SIZE.md)。视觉导入的“待做”明确为用户搁置，等再提才开发。


2026-10-09。源版本 1.1.0-beta.24，Android versionCode 73，离线缓存 v30；实体协议保持 8。

## 影片与打包

当前使用的 29 段 3D 影片原本全部为 30 fps。本次保持帧率、原横竖分辨率、帧数、时长和 AAC 音轨，仅压缩视频码率。总计从 280,283,220 字节降为 103,388,783 字节，减少约 63.1%。这是有损视频压缩，密集粒子/细纹理可能有轻微损失；不宣称画面无损。

压缩发生在构建后的 `dist/client/cinematics`。`public/cinematics` 的原始影片和渲染 manifest 不修改，保留再次调节质量的母版。过期素材仍由既有资产准备步骤排除；刹那旅程的音源 MP4、立直音源和其他歌曲均不参与视频压缩。

参数：H.264 High 4.1 / yuv420p，x264 slow，CRF 25，最大码率 5 Mbps，缓冲 10 Mbps，音轨直接复制，faststart。未缩小画面或抽帧。每个首次编码结果完整解码检查尺寸、帧数、帧率、时长，比较 AAC 数据哈希，并测量整片 SSIM；低于 0.92 即停止等待人工调整。当前最低为 0.93308。缓存以源哈希、编码配置、FFmpeg 版本索引，再核验缓存哈希；后续打包可复用。

Android 构建新增 Python（3.11+）与支持 libx264 的 FFmpeg 依赖。`scripts/build-android.ps1` 可通过 `-CinematicPython`、`-CinematicFfmpeg`、`-CinematicCache` 指定位置；默认分别为 python、ffmpeg、.tmp/cinematic-cache。顺序为网页构建 → 清理过期素材/可选 PNG 优化 → 影片压缩 → 离线清单 → Capacitor 同步 → Android 构建。压缩报告输出 `.tmp/cinematic-compression.json`，包内 cinematic manifest 同步更新压缩后字节数与哈希，并保留原始信息供追溯。

## 歌曲优先级与生命周期

实体 Host 接受《断序杂音》或《宿星审判》发动后，顺序为代码前奏 → 3D 影片 → 完整回桌尾段 → 对应歌曲。自动歌曲仅播放一次；原立直曲暂停并保留位置，歌曲结束后，若立直播放条件仍成立，继续原立直曲。若已无有效立直，不启动立直音乐。

同一事件去重。新的这两种技能完整演出结束后，以新歌替换旧歌，不叠播；演出期间保留原有背景音乐压低机制。用户主动打开 NFC 音乐播放器时暂停自动背景音乐，关闭后恢复。切后台暂停，返回前台继续；离开 Host、关闭对局音乐或进入寂静/暗夜效果时释放自动歌曲。歌曲不写入保存状态，重新载入对局不补播。

跳过、返回、进入后台中断演出、影片失败不启动歌曲。减少动画模式在简化演出完成后启动；遥控端、技能库预览不会接歌。歌曲加载/播放失败会释放优先权，避免永久压住立直音乐。

复用原 `riichiMusicEnabled` 保存字段，界面统一称“对局音乐”，不迁移或清除用户设置。播放音源从既有 NFC 注册表读取。公开源仍为空音源，不加入私人歌曲/曲绘；私人 APK 在隔离目录注入原有资源。

## 验证范围

新增音乐调度与影片结束原因的回归测试，覆盖优先级、原进度恢复、无立直、事件去重、连续替换、过期回调、前后台、独立播放器暂停、失败与清理。类型检查和完整核心回归通过。影片编码逐项核验；包装核验将压缩后 APK 文件与报告比对、母版与源哈希比对，不能继续用“APK 视频与母版字节相同”作为压缩后的验证标准。

真实浏览器与正式 APK 构建的验证记录见交付目录报告。浏览器不能代替 Android 真机的扬声器、厂商 WebView 和 NFC 验收。不改实体计分、技能结算、虚拟规则或 Host 暗牌边界；视觉导入仍待做。
